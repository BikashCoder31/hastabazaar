Keep public maintenance on and writers paused. Record the failing phase, last completed journal entry, safe error code and actual database fingerprint. MariaDB can commit DDL statement by statement. Reconcile partial changes before any retry. Preserve the failed state, receipts and backups for diagnosis.

Before reopening, use only the owner's reviewed recovery procedure if the fix will miss the cutoff. Restore the verified pre-change database and matching app and security state only after explicit approval and verification of the recovery target. After reopening, account for newly accepted orders and payment activity before considering any database restore. Keep the verified recovery artifacts through the agreed retention window.
