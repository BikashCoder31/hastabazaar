# Homepage Hero Carousel — Design Specification

**Version:** 1.0  
**Date:** 21 September 2026  
**Environment scope:** disposable local staging only  
**Production deployment:** not authorized

## 1. Approved outcome

The homepage hero becomes an accessible, configuration-driven carousel.

- The current hero is preserved exactly as protected slide 1.
- Super Admin can manage up to seven additional slides, occupying positions 2 through 8.
- The first staging release adds two new editable slides, so the carousel initially contains three published slides.
- Additional slide slots remain empty until a Super Admin supplies and publishes valid content.
- An editable slide may use either a still image or a short MP4 video.
- Routine slide changes must not require editing code or redeploying the application.

The current slide remains the permanent fallback. No setting, request, or direct API call may delete it, replace its content, move it from position 1, or turn it off.

## 2. Reused project foundations

The implementation will reuse:

- the existing Embla-based carousel component and its keyboard controls;
- the existing versioned Business Settings publication, preview, effective-date, permission, and history workflow;
- existing bounded image and MP4 validation patterns;
- existing environment-isolated storage bindings and local staging media handling;
- the existing homepage editorial layout, actions, typography, and responsive breakpoints.

The existing `/admin/homepage` page currently manages product visibility only. It will gain a separate **Hero slides** area without changing product-visibility behavior.

## 3. Slide model

### 3.1 Protected slide 1

Slide 1 is a code-owned system slide with the current content and image:

- eyebrow: “Nepal’s handicraft marketplace”;
- heading: “Handmade today for a brighter Nepal.”;
- body copy currently displayed on the homepage;
- primary action: “Explore the collection”;
- secondary action: “Meet our makers”;
- current principles row;
- image: `/homepage/nepal-craft-hero.webp`;
- current accessible image description and image note.

The carousel component renders this slide from a protected system constant. The admin page shows a read-only preview labelled **Protected current slide**.

### 3.2 Configurable slides 2–8

Each configurable slide contains:

| Field                        | Requirement                                                |
| ---------------------------- | ---------------------------------------------------------- |
| Stable slide ID              | Generated by the server; immutable                         |
| Position                     | Integer 2–8; unique within a published version             |
| Enabled                      | Boolean; enabled slides count toward publication readiness |
| Eyebrow                      | Required; 3–60 characters                                  |
| Heading lead                 | Required; 3–90 characters                                  |
| Highlighted phrase           | Optional; maximum 60 characters                            |
| Heading tail                 | Optional; maximum 90 characters                            |
| Body copy                    | Required; 20–240 characters                                |
| Primary action label         | Required; 2–40 characters                                  |
| Primary action destination   | Required allowlisted internal path                         |
| Secondary action label       | Optional; required when a secondary destination exists     |
| Secondary action destination | Optional allowlisted internal path                         |
| Media type                   | `image` or `video`                                         |
| Media ID                     | Required reference to owned, validated hero media          |
| Image alternative text       | Required for an image; 10–180 characters                   |
| Video poster media ID        | Required for a video                                       |
| Video accessible description | Required for a video; 10–180 characters                    |
| Image note                   | Optional; maximum two lines and 100 characters total       |

Destinations are limited to safe internal storefront paths such as `/shop`, `/sell`, `/#makers`, and `/#occasions`. Credentials, protocol-relative URLs, external URLs, script URLs, and staff-only destinations are rejected server-side.

### 3.3 Collection rules

- A published carousel must contain the protected slide plus at least two enabled configurable slides.
- A maximum of seven configurable slides may exist in one published version.
- Positions are contiguous from 2; publishing rejects gaps, duplicates, or more than seven configurable slides.
- Drafts may be incomplete, but preview clearly identifies every validation problem.
- Publishing fails closed if referenced media is missing, invalid, unowned, archived, or unavailable in the current environment.
- The storefront keeps using the latest valid effective published version if a later draft or scheduled version is incomplete.

## 4. Initial editable slides

The staging seed adds two fictional editorial slides that make no claims about a specific real maker.

### Slide 2 — Maker stories

- Theme: the human process behind handmade work.
- Art direction: a face-free close view of artisan hands shaping or decorating craft.
- Suggested heading: “Every piece begins with a pair of hands.”
- Actions: “Meet our makers” and “Share your craft.”
- Destinations: `/#makers` and `/sell`.

### Slide 3 — Meaningful gifts

- Theme: thoughtful handmade gifts for occasions.
- Art direction: an editorial still life of Nepali pottery, Lokta paper, textile, and small craft objects; no bags and no identifiable people.
- Suggested heading: “For every moment, something meaningful.”
- Actions: “Shop gifts” and “Explore the collection.”
- Destinations: `/#occasions` and `/shop?category=gifts`.

The exact staging copy and generated assets remain editable through Super Admin before any separately approved production release.

## 5. Image and video handling

### 5.1 Images

- Accept JPEG, PNG, and WebP whose decoded content matches the declared type.
- Enforce a bounded request body and a maximum decoded dimension and pixel count.
- Normalize accepted files to a safe WebP derivative for display and strip metadata.
- Require a wide hero-compatible crop during preview; do not stretch a mismatched source.
- Store original name only as private administrative metadata.

### 5.2 Videos

- Accept validated MP4 only in the first release.
- Maximum upload size: 20 MB.
- Maximum duration: 15 seconds for hero use.
- Require a validated poster image so reduced-motion users and unsupported browsers receive a complete visual.
- Render videos muted and `playsInline`; never autoplay audio.
- Only the active slide may play. Inactive videos are paused and reset.
- A visible pause/play control pauses both carousel advancement and active video playback.
- When reduced motion is requested, video does not autoplay and the poster is shown by default.
- Essential claims, actions, and meaning remain in HTML text rather than existing only in the video.

Hosted video links are not included in the first implementation. Existing bounded upload handling is safer and avoids activating an unapproved external provider. A hosted-link option can be proposed later if verified deployment storage or playback limits require it.

## 6. Storefront behavior

- Render the protected slide first during server output for resilient content and search visibility.
- Hydrate the existing Embla carousel on the client.
- Advance image slides after six seconds.
- Advance a video slide when its video ends, with a hard maximum of fifteen seconds before advancement.
- Pause automatic advancement while the hero is hovered, contains keyboard focus, the document is hidden, or the visitor has paused it.
- Reset the timer after a manual navigation action.
- Support previous/next buttons, pagination indicators, touch swiping, and Left/Right Arrow navigation.
- Label the region as a carousel and each item as “Slide N of M.”
- Do not use an assertive live region for automatic changes. Announce the selected slide only after a manual action.
- Respect `prefers-reduced-motion`: disable automatic advancement and use non-animated selection.
- Load slide 1’s image eagerly. Load later images lazily and defer video data until the slide is near activation.
- Maintain the current desktop split composition and mobile stacking without horizontal overflow or layout shift.

## 7. Super Admin workflow

The `/admin/homepage` page receives a Hero slides panel above the existing product controls.

The panel provides:

- a read-only preview of protected slide 1;
- cards for slides 2–8 with add, edit, enable/disable, move up, move down, and remove-from-draft actions;
- image or video upload with a poster requirement for video;
- desktop and mobile preview modes;
- a readiness summary showing valid slide count and specific outstanding fields;
- draft save, preview, immediate publish, future-effective publish, and restore-as-new-version actions;
- immutable change history showing actor, timestamp, effective date, and before/after version references.

The editor uses explicit move controls instead of drag-only ordering so it remains keyboard accessible. Removing a slide from a draft does not delete media or alter a published version.

Slide content uses the existing simple public-content change process. Only an active Super Admin with the existing homepage/business-content management authority may mutate or publish it. Server checks enforce all permissions and revision tokens; hiding controls in the browser is not treated as authorization.

## 8. Authoritative configuration and storage

Add a typed `homepage_hero_slides` Business Setting. Its value contains only configurable slides 2–8 and references hero-media IDs. The protected first slide remains code-owned and is combined with the effective setting at read time.

Add an additive `homepage_hero_media` table containing media identity, object key, normalized MIME type, byte size, dimensions, optional duration, creator, timestamps, and archive state. Media bytes use the environment’s existing storage abstraction; no production binding is accessed from local staging.

The Business Setting version is authoritative for:

- which configurable slides are published;
- ordering;
- text and actions;
- media references;
- the effective period.

The media table is an asset registry, not a second source of publication truth. A media record is publicly served only when referenced by the current effective published carousel. Admin preview uses an authenticated route.

The migration must be implemented for the project’s local/D1-compatible path and Babal/MariaDB path. It does not justify removing either D1 or R2 compatibility.

## 9. APIs and permissions

Planned endpoints:

- authenticated Super Admin upload and media-inspection endpoints under `/api/admin/homepage/hero-media`;
- the existing Business Settings mutation and publication workflow for `homepage_hero_slides`;
- a public read-only media endpoint that serves only currently published slide media;
- authenticated preview access for draft media.

All mutation requests require bounded bodies, trusted origin protection, current revision tokens, idempotent request IDs where applicable, and server-side Super Admin authorization. The API never accepts object keys, publication state, or media ownership from the caller as authoritative.

## 10. Failure and rollback behavior

- If configurable settings cannot be read or validated, show protected slide 1 rather than a broken carousel.
- If fewer than two valid configurable slides are effective, show only protected slide 1 and surface an operational warning to Super Admin; never expose blank slides.
- A failed media request shows the validated poster or protected-slide fallback without shifting the page.
- Restoring a prior configuration creates a new version; it never rewrites history.
- Media referenced by any retained version is not destructively removed.
- The first release archives unused media but performs no automatic irreversible purge.
- Rolling back application code leaves protected slide 1 available and does not alter unrelated homepage product controls.

## 11. Test requirements

### Configuration and permissions

- Protected slide 1 is always first, unchanged, and absent from editable payloads.
- Two through seven configurable slides validate; zero, one, eight, duplicate positions, gaps, and malformed values fail publication.
- Unsafe destinations and staff-only paths are rejected.
- Non-Super-Admin users cannot create media, edit drafts, preview private media, or publish versions.
- Concurrent stale revisions cannot overwrite a newer draft or publication.
- Future-effective versions do not appear early, and restoration preserves history.

### Media security

- Valid JPEG, PNG, WebP, and MP4 fixtures are accepted within limits.
- Spoofed MIME types, malformed media, oversized uploads, excessive dimensions, videos over 15 seconds, and unowned media IDs are rejected.
- Metadata is removed from normalized images.
- Draft and orphaned media are not available through the public endpoint.
- Local staging cannot read or write production media bindings.

### Carousel behavior

- Initial staging fixture renders exactly three slides: protected slide 1 plus two editable slides.
- Autoplay advances in order and wraps after the final slide.
- Hover, focus, hidden-document state, manual pause, and reduced motion stop automatic advancement.
- Previous, next, indicators, keyboard navigation, and touch interaction select the correct slide.
- Only the active video plays; leaving it pauses and resets it.
- Video ending advances the carousel; poster fallback remains usable.
- Manual navigation receives an appropriate announcement without noisy automatic announcements.
- Existing hero links, category overlap, responsive layout, and principles remain functional.
- Desktop and mobile visual QA show no clipping, overflow, blank frames, or layout shift.
- Existing homepage, footer, seller, order, invoice, settlement, and configuration regression tests remain green.

## 12. Staging rollout

1. Add schema and MariaDB migration artifacts without running them against production.
2. Add typed configuration, media validation, repository, and permission tests.
3. Add the Super Admin editor and authenticated preview.
4. Add the storefront carousel with protected slide 1.
5. Create two fictional staging slides and safe editorial assets.
6. Run automated tests, type checking, lint, build, media-security tests, and desktop/mobile visual QA.
7. Deliver local self-test instructions covering content editing, image and video slides, scheduling, rollback, permissions, reduced motion, and failure cases.

Production remains blocked pending separate approval, verified production storage/video capacity, deployed schema verification, backup/rollback readiness, and review of the final public content. No production migration, upload, setting change, or deployment is part of this design approval.
