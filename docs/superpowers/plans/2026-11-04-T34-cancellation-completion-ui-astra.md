## Defect and implementation

An original cancellation proof commits before managed earnings and invoice hooks. The prior shared browser hook accepted proof only on HTTP200 and then treated GET proof as completion. A real recorded503 was described as an unknown cancellation; a subsequent read-only GET discarded its reference even while native settlement remained unfinished.

The approval API now reports the original `recorded:true` decision independently from `settlement:'unconfirmed'|'confirmed'`. GET remains read-only and deliberately reports settlement **unconfirmed**, because the original decision proof alone cannot establish whether every post-commit hook completed. A successful original exact POST returns confirmed only after the existing hooks return. A recorded503 never implies approval failure or actual refund/payment completion.

An explicit continuation POST carries only `{reviewId,action:'approve',clientAttemptId,continuation:true}`. It cannot include new notes, fingerprints, form answers or replacement terms. The server requires the same authenticated original proof, deterministic `review:<reviewId>` event, approved review/order/actor/supplier scope and original configured/core answer record. It recomputes the original catalog digest from the immutable event terms, original saved fingerprint, original version and answers. Missing, mismatched or legacy unproven history cannot be adopted. No current form reapproval is required for an already committed decision, and no new decision can enter this path.

Only the existing native managed accrual and invoice hooks run, with their original `:managed-accrue`, `:earned:<entitlement>` and `:managed-invoice:<group>` identities. Existing per-hook atomic role, authenticated-subject and customer/supplier-independence guards remain. Current source/independence is checked again after the hooks, and the route rechecks exact current identity after final reads and failures. Role/subject denial returns403 and hides the private parent. Independence remains the existing native cancellation-conflict policy; for a known committed approval, a blocked continuation returns recorded503/unconfirmed rather than inventing a global authorization denial.

The shared hook opts into this protocol only for staff cancellation approvals. It accepts correctly bound recorded503 as proof of the decision, preserves the opaque reference and offers **Continue original settlement**. After reload it first offers GET; once original proof is read, it offers the explicit continuation. Only confirmed continuation clears the reference. Exact original decision wires remain owning-instance RAM only; session storage still contains only action/requestId. Generic fulfillment/rejection recovery, denial-before-body-parse, same-reference retries, earlier-unknown precedence and cleanup-failure behavior are retained.

The actual async CancellationReviewSection is inspected against the memory database by the new browser case. Its approved row returns `canDecide:false`; those real returned props feed the mounted control after reload. New decisions remain disabled while recovery stays available. The admin order page already includes this section; no parent production change was needed.
