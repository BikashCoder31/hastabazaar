## Reconciliation and changes

Reused the optional registration parser/API, owned draft/upload store, actual email-verification check, editable address copying, agreement expansion, submission receipts and separate dashboard sections. Existing blank-intake/API tests confirm that omitted information is accepted without fabricated consent or phone/email verification.

- International phone input now retains supported national lengths; Nepal still requires exactly ten digits and no phone OTP. Other countries use structural numeric bounds within the E.164 15-digit total, not a claim of carrier/ownership validation. Reference: [ITU E.164](https://www.itu.int/rec/t-rec-e.164/en).
- The draft hook recovers a committed 503 through authoritative readback. If readback also fails, retry keeps the exact original change identity/payload before processing newer edits. A successful response must match the submitted revision/attempt.
- Account changes remount private form state. Submitted-registration corrections also save private progress, scoped to the submitted version. Older progress requires an explicit comparison/choice and cannot silently overwrite current submitted values.
- Conflicting tabs retain local entries, expose the latest saved progress and require an explicit choice. Failed/offline saves preserve input and block intercepted navigation. Submission stops when current progress cannot be confirmed.
- Draft save/discard now recheck an active eligible owner with an existing application or explicit registration start; save checks repeat inside the transaction. An account revocation race rolls back the revision.
- Existing application owners entering `/sell/apply` continue to `/seller/registration`. Successful new intake points to the unified `/seller` workspace.
