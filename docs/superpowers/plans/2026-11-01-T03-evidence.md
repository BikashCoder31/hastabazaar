Status: in progress, not whole-task verified.

Implemented in `lib/forms/{core-contracts,runtime,submission,types,catalog-changes}.ts` and `lib/db/repositories/form-answers.ts`:
- Missing optional registration/product/profile/maker-profile/stock publications use feature-owned core contracts and existing domain validators. No configuration is inserted or published. Core-only evidence uses `form.core_answers` audit receipts in the parent transaction; history/replay understand those receipts. No custom/protected answers are invented. Unknown extra answers reject explicitly. Registration still requires the verified signed-in owner and its actual optional-intake record; legacy strict application rules are preserved.
- A concurrent publication aborts the parent transaction. Financial/security forms still fail closed. Invalid metadata remains unavailable. A temporary read failure can use an eligible server-validated definition cached for at most 60 seconds only after an independent authoritative query confirms the exact JSON/current publication; full DB outage, expiry and a newer publication reject recovery. No client cache is trusted.
- Automatic compatibility covers whitespace/order changes to the preceding definition. Wording/choices/requiredness/numeric changes require review with a change summary. Snapshot retains both current validation version and originally presented version. Exact compatible replay retains its original snapshot after later publications.

The panel compares previous/current wording, explains structural exclusions, requires a reason and offers a 24-hour acceptance window or explicit revocation. Structural/requiredness/choice-value changes cannot be waived. Source versions, current authority and revocation are rechecked atomically; command receipts preserve concurrent/exact retries. Completed answers remain recoverable after revocation; new actions reject. Each policy change emits one actor-self Super Admin email/bell pair, and superseded policy notices cancel.
