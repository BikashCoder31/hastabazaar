## Original evidence and correction

All four original controls omitted displayed-actor intent. Actual native fixtures reproduced twelve failures: four stale displayed-A/current-B writes, four missing original GET readers, and four authenticated-subject changes accepted at commit. The old mounted controls independently reproduced four real native writes as B while displaying A. These were actual accepted decisions, not mocked success assumptions.

The protected permission, identity verification, disposition and seller bank review routes now enforce displayed actor intent and trusted current authenticated subject. The native commands retain their original receipt source, digest, result and direct-domain returns. A separate proof event is appended atomically with a newly committed effect and its unchanged generic receipt, using the existing immutable `seller_protected_change_events` table. There is no migration or historical backfill. A direct legacy command without original authenticated-subject proof remains GET404/unconfirmed; replay does not adopt it or append new proof. Original permission IDs are still returned from the original receipt, including after a later lawful rejection.

GET checks the original actor, authenticated subject, action, source and request nonce against immutable history and the matching unchanged command receipt. It repeats current native authority and authenticated-session checks, including failures while reading the outcome. It does not accept invitations, provision staff, execute transaction guards, or write any result. A changed current case or a later lawful decision does not rewrite the original historical result. The internal proof event is omitted from business-history presentation before ordering; the actual permission, verification and disposition events remain visible.

Only an exact proven pre-write rejection can release a first attempt. Invalid review fields and freshly observed stale case/bank revisions receive the original actor/action/source/nonce marker. Batch failures, receipt conflicts, lost acknowledgements and missing legacy proof remain uncertain. A later pre-write marker cannot settle an earlier unknown attempt.

## Client and parent boundaries

The four clients use one bounded recovery form, scoped to actor/action/source. Private notes, attestations and the exact retry wire stay in RAM. Only the opaque UUID reference is retained in session storage, and it must be retained successfully before sending. A reload offers original GET recovery and never rebuilds a POST from private values. Recovery components stay mounted when the corresponding decision is no longer available. A current source change preserves notes but requires explicit review and fresh evidence confirmation.

HTTP401/403 is handled before reading any body. Both protected-change detail and seller detail use the existing staff review boundary so current denial curtains private evidence, history and sibling inputs immediately. Late callbacks cannot alter another actor/source scope. The protected page presentation was extracted into a pure workspace component to test the actual complete parent; its server reader keeps the existing default observation clock. The frozen document boundary and document native implementation were preserved.
