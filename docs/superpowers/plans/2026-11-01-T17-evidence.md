## Implemented behavior and source mapping

- `lib/products/intake-workspace.ts` atomically saves bounded raw answers, actual offer matrices, private product-review references and completed upload references. Empty/zero-cover intake creates no product. An earlier T12 detail-only draft gains its full workspace snapshot through the same reference before sending.
- Submitted versions are immutable and separate from later private edits. Exact version/case comparison is required for supersession. Help/Send replay the same transition without duplicate cases/events/tasks. Newly approved category guidance can make the same facts complete while preserving the original unfinished assistance deadline and the separate first complete-review clock.
- `intake-assistance.ts` retains sourced factual proposals. The owner explicitly accepts/declines them; acceptance changes the private draft, never the frozen submitted version. No-op proposals and newly attached unshared media are rejected. Commit-time ownership/staff guards and exact receipts protect races, permission loss and uncertain responses.
- `intake-media.ts` retains upload identity before object storage and reconciles lost acknowledgements against the exact object metadata/digest. Only completed owned uploads enter snapshots. Owner/staff media readers enforce their actual draft/case scope. The UI can recover an incomplete upload after reload with its original request and file, including correcting an accidentally selected different file.
- `intake-form-context.ts` binds ordinary extra answers to server-owned historical question metadata. All intake questions remain optional; invalid bounded numeric text is retained as an advisory issue. Private pricing controls and native commercial fields cannot be injected as custom context. Published configuration changes do not relabel earlier answers or candidates.
- `intake-history.ts` and the owner history API provide paginated version references and exact read-only snapshots. Adopting updated questions is explicit; prior answers remain accessible in their saved versions.
- New seller/applicant entry points use `ProductIntakeWorkspace`: Basics, Photos & details, Review; actual `VariantEditor`, optional owner-private `PriceProfitPreview`, truthful selected-offer preview, separate publication/ordering guidance with field links, optional media/occasions and explicit send-context review. Save and upload outcomes are distinguished. Successful files are not reuploaded to recover another file.
- Staff use the same frozen case with current category guidance, shared-photo choices, sourced proposals, recorded responses and comparison/retry controls. Public parent-price controls do not compete with actual offer rows.
- Product question-config reads now follow active current draft ownership, without seller approval or an unnecessary published-customization dependency. The existing empty core contract is read without creating configuration data. Unrelated accounts and inactive users remain denied.
- Shared task and notification adapters use the exact current case event. Superseded notices are hidden, repeated transitions do not duplicate messages, and acting Super Admin oversight remains. Product assistance in the staff queue names the seller as next actor when the case waits for their response.
