## Actual native contract and changes

The old cancellation client generated a UUID but never sent it. Its native economic references are intentionally `review:<reviewId>` and `review-reject:<reviewId>`; these remain unchanged. A new optional `clientAttemptId` binds an additional original-action proof to actor, authenticated subject, review, action and exact body. The proof uses the existing immutable audit command columns and is inserted in the **same batch** as the actual cancellation approval/rejection. It is not inferred from current state or retroactively inserted for a legacy replay. Direct domain return shapes and no-clientAttemptId API behavior remain supported.

Seller fulfillment already had an exact native command receipt, but returned only `{ok:true}`. Its current route now returns strict actor/order/action/request proof alongside the compatible `ok` field. The existing per-item fulfillment transaction additionally commits the original authenticated-subject proof and current owner/approved-seller/role guard. Existing stock, order aggregation, preparation clocks, holds and durable notifications remain authoritative. A replay with new proof requested cannot adopt a legacy core receipt.

Both routes now expose read-only original GETs. Proof contains no private wire or authenticated subject in its public response. Current actor/role/ownership is rechecked after reading, including failure paths. Seller intent is rejected using an existing-only lookup before any old account binding; staff uses the existing reject-only intent helper. Original GETs never provision identities or write business/receipt data. Current role/subject races at commit roll back effects and proof together. Original fulfillment-start proof remains historical after a later actual ready-for-pickup action.

Both mounted controls use actor/source-owned instances and ignore retired callbacks. Only `{action,requestId}` persists; exact private POST bodies stay in owning RAM. Reload offers GET, even after the cancellation review closes or eligible fulfillment controls disappear. Legacy full fulfillment wires are scrubbed to references without rebuilding a POST. Unsupported legacy cancellation UUIDs remain unconfirmed because they never reached the server. Invalid/conflicting references block new actions; no browser-confirm discard or GET-absence reset remains.

Native401/403 (and POST404) are handled before parsing any body. Seller denial uses the existing Seller layout curtain. Cancellation uses the existing Staff review boundary around the full private admin order and its review section, so sibling fields disappear even if refresh cannot complete. Configuration denial is also wired into that boundary. Matching first `before_write` form rejection allows explicit review of the current form while retaining the note; an earlier unknown response wins over any later conflict. Immediate duplicate handlers cannot generate a second nonce. A valid native confirmation remains confirmed if browser cleanup fails; its opaque marker is retained without exposing a retry or enabling a second write.
