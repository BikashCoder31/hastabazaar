Implemented so far:

- Manual-bank checkout composes the original company receiving instructions, 24-hour window, exact offer reservations, cart clearance and original financial snapshots into the existing recovered checkout transaction. The internal method remains separate from COD; public capabilities stay false pending integration evidence.
- Customer claims, independent company receipts and explicit exact allocations are distinct records. Optional reference/files do not block an otherwise complete amount/date claim. Claims cannot mark payment paid. Actual bank time and database confirmation time are separate. Receipt balances, order/window revisions, personal interests and current staff grants are checked inside the transaction.
- Receipt verification is explicitly delegable and absent from legacy Admin defaults. The delegated-Finance test exposed the old assumption that configurable permissions equal default permissions; the defaults and grant catalogue are now separate. No real permission records were changed.
- Native cutoff projections retain the original deadline and one fixed four-hour buffer based on committed pre-cutoff claims or positive partial allocations. A late claim cannot backdate eligibility. A final allocation guard uses the previously committed cutoff so the same allocation cannot create its own extension.
- Expiry closes the original order once, releases the exact reserved offer rather than the parent inventory, and uses the existing native cancellation wallet ledger. Partial real money remains attributed to the expired order with a Finance exception. Original financial/offer snapshots and promo-use history remain retained.
- Paid and released are separate facts. Release checks original reservations and existing-work restrictions; it does not require acceptance of newer seller terms. An unreleased paid order receives a Finance case without another payment demand.
- One six-hour-before-deadline reminder uses the shared notification channels and current-source suppression. Claims suppress queued reminders. Finance exceptions also use the existing shared outbox.
- Source migration 0098, typed declarations and MariaDB counterpart are being maintained. The stock event history is preserved while allowing a null actor for an actual automated expiry. No source migration or generated recovery script was applied to the canonical database.
