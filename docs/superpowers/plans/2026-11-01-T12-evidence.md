## Source reconciliation and changes

- Read the approved retail/category/variant design, including its expandable taxonomy, precise publication-versus-ordering requirements and 3/100 rules, plus the later optional-intake/support amendment. The existing `ProductSubmissionForm`/`parseProductSubmission` still enforce a complete packet and gift occasions. They remain legacy consumers to replace through T17/T18; their validation was not weakened into an unsafe public-product write.
- Added `category-fields.ts`: stable supported public field identities, nine discoverable groups, explicitly optional intake, precise common/category publication issues and separate ordering fact issues. Missing price is never Free; incomplete numeric text remains text. Unused-new condition is explicit, unsupported conditions fail publication guidance, relevant condition wording is flagged, offered warranty needs its actual provider/duration/terms, and conditional Yes/No facts cannot bypass a requirement with an unknown value. No private cost, profit, bank or PAN field is exposed by template mapping.
- Added `category-contracts.ts`: current Super Admin policy authority, immutable versions and exact request replay; bounded owner-only private drafts and immutable saved revisions. Empty drafts, invalid draft money and unknown/disabled categories can be retained for assistance. No draft save writes products, stock or public facts. Category switches retain answers and a change record; editorial labels retain the same field keys. Current policy guidance is recomputed without inventing facts or silently using a permissive general policy.
- Added source migration `0087_category_contracts_intake.sql`, typed tables and source-only MariaDB counterpart. No existing category was automatically mapped, enabled, reset or replaced. Native MariaDB is unavailable; generated SQL is not engine evidence.
- Extended existing taxonomy management with Super Admin parent changes, ancestor/cycle and current-parent guards. Existing category/occasion URL slugs are retained; display labels can change. Category counts are not capped at four. Existing IDs, public filter routes and product associations remain intact.
- Added restricted Category Policy management to `/admin/catalog`, with supported-field wording, recommendations, explicit publication/ordering rules, affected product/draft counts, retained policy history and exact uncertain-request retry. Added authenticated `/api/admin/category-contracts` and owner-scoped `/api/seller/product-intakes` APIs. Parent/category authorization is enforced again at commit.
- Added `CategoryDetailGroups` for the later unified editor: searchable/collapsible mounted groups retain input, every control is skippable and missing-category guidance leads to help. Photos and gift occasions use integration callbacks rather than asking sellers to enter storage keys or taxonomy IDs. The help callback does not itself claim a support request was sent. Actual media, discovery, support-send and editor navigation wiring remains T17.
- Category policy publication uses current-source bell/email events, safe links and Super Admin actor-self oversight. Draft keystrokes/saves create no operational notices. Full producer/delivery integration remains T29.
