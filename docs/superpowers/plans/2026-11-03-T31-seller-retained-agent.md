## Investigation and design

- New managed optional intake still displays a generic Government ID type picker. The number field already says Citizenship number, so an old saved passport can be mislabeled even though its type is retained.
- `useSellerDraft.restoreAnswers` intentionally skips hidden controls. Its route-state contract currently has no identity type. Replacing the picker with a hidden citizenship constant alone would corrupt historical interpretation. The narrow design is explicit identity route state restored from the owned draft; new empty intake uses citizenship, a retained legacy type/reference stays labeled as recorded, and a deliberate unverified correction cannot silently reuse the old reference. Verified fields/evidence remain locked. No native identity enum or historical row conversion is proposed.
- Native draft GET/PUT/DELETE already require the actual internal `X-Draft-Account`, including a first unsaved revision. This protection is real and must remain. Client authority denial still needs a private-field curtain/current-view refresh.
- `SellerRegistrationDetails` keeps its `record` when the account props change; its GET effect depends only on refresh and has neither intended actor nor a late-response scope fence. A's stored registration can therefore become B's initial defaults, after which a genuinely authorized first B draft can capture them. The fix must bind the loader and its state to the actual internal account, not weaken the native draft guard.
- Registration GET originally returned B's private retained answer payload to an A-intended request. The native receiver already resolves customer/terms without provisioning; it now applies the shared reject-only internal actor assertion for GET and submission. Header-absent legacy calls remain compatible.
- Private workshop profile reads/updates intentionally require an approved seller, and the actual page omits that legacy private form before approval; this is not an applicant form/API contradiction. The separate public profile and contact/location workflows remain distinct.
- Bank POST already carries an internal account guard, but the retained bank control's initial/focus reader and case/default state need actor/source testing. Profile/document/protected-change regions are reserved to this agent; Finance confirmed no overlap (its recovery action remains separate).
