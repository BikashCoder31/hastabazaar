Removing the last pending supplier portion can make a mixed order delivered, but the existing managed earnings and managed invoice hooks run after that transaction. A lost commit acknowledgement or later hook failure therefore leaves a recorded cancellation with unfinished native settlement. The newly added route returned its proof before reaching the repository's existing exact-replay continuation.

No proof is retroactively created for a legacy result; changed wire and replacement nonce cannot adopt the original decision. GET remains a read-only historical-decision lookup and never invokes settlement.

Staff cancellation hooks now fence each separate native mutation batch with current `order.manage`, exact actor/authenticated-subject and customer/supplier independence checks. Guards run inside the same batch as that hook, with the native result positions preserved. This fixes the reproduced commit race where a revoked staff actor received 403 only after earnings had already been written. A failure at invoice commit retains the already committed earning and rolls back only that invoice attempt. Existing customer and no-subject native semantics remain compatible.

When an approval POST fails after its decision committed, the route reads only its atomic original proof and rechecks current identity after the read, including read failures. A known decision returns HTTP503 with its unchanged `recorded:true` reference and an explicit message that cancellation is recorded but settlement continuation is not confirmed. An exact replay that fails has the same distinction. No current order state is used to invent proof; unreadable/missing proof remains unconfirmed, and current identity loss wins with403 before exposing history.
