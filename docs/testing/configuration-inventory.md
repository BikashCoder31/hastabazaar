# Hastabazaar v1.2.1 — configuration inventory

All controls below use the typed, versioned Business Settings registry. Unknown keys, executable formulas, raw SQL, direct balance edits and security-bypass switches are rejected. Only a Super Admin can create a change. **Controlled** changes require a different Super Admin to approve; **simple** changes use preview plus publish/schedule. Reversal always publishes a new version, so no historical record is edited.

| Control | What it changes / allowed values | Timing and affected records | Notice / acceptance | Test and safe reversal | Remaining work or live dependency |
| --- | --- | --- | --- | --- | --- |
| Independent seller commission | 0–10,000 basis points; independent-seller orders/settlements only | Future-effective; snapshotted per new order item; existing items unchanged | At least 15 calendar days and renewed seller acceptance of the exact setting/agreement version | Controlled maker-checker tests; reverse with a new future version | Accountant confirms service-tax treatment and reviewed live text |
| Managed sale-linked platform retention | 0–10,000 bps; retained amount, with maker receiving the exact remainder | Future-effective and snapshotted per Managed Maker order item | Reviewed Managed Maker agreement required for live use | NPR 1,000 → 90 retained + 910 entitlement; refund/config-history tests; reverse prospectively | Tax/withholding and live agreement review |
| Managed Maker program mode | `applications_only` or `activation_enabled` | Future-effective; affects onboarding/review/catalogue gate, not historical orders | Controlled contractual change | Readiness/capability tests; revert with new version | Live activation remains blocked until company/program requirements are verified |
| Managed Maker active model | `null`, sale-linked v1, or fixed supplier-price v1 | Future-effective; new activation/order scope only; model/version snapshots preserved | Controlled contractual change and applicable agreement acceptance | Capability, activation, both-model and open-order history tests | Adviser/accountant approval for whichever model is activated live |

| Managed adjustment reasons | Normalized approved code list | Future-effective reason choices; adjustments are append-only | Agreement/policy notice where reasons change rights | Adjustment/idempotency/refund tests; later version | Reviewed live reason policy |
| Product material suggestions | Bounded safe text list; sellers may add accurate alternatives | Immediate editor suggestions; never rewrites products | No renewed agreement | Validation/editor tests; republish prior list | No infrastructure work |
| Official social links | Six validated HTTPS host-specific URLs supplied by owner | Immediate public footer/content; no transaction effect | No renewed agreement | URL validation, preview and footer build tests; republish prior version | No infrastructure work |
| First-party analytics policy | Enabled flag, bounded retention, excluded domains/path prefixes | Immediate future event collection/retention; does not alter transactions | Privacy publication before live enablement | DNT/GPC, bot, allowlist, deletion and access tests; disable/restore version | Live privacy decision; remains off by default |
| Recently Viewed policy | `maxItems` 1–50 and `retentionDays` 1–365; defaults 12/90 | Immediate per-entry history behavior; no order impact | No renewed agreement | Expiry/isolation/current-catalogue/clear tests; republish prior version | No infrastructure work |

Business Settings cannot modify company registration, legal seller/issuer facts, existing balances, historical invoices, agreement text, database contents or permissions. Those remain in their dedicated verified workflows. A capability must be implemented and tested before a configured value can activate it.
